# 1️⃣ 개념 정리

아래 키워드 중 중요하다고 생각한 개념을 2개 이상 골라 짧게 정리해주세요. 3개보다 더 많이 정리하고 싶다면 자유롭게 항목을 추가해도 좋습니다.

이번 주 키워드:
- SELECT
- FROM
- WHERE
- 조건식
- ORDER BY
- LIMIT
- 테이블 구조 확인

## 01.

```
개념 이름: SELECT
개념 설명: 테이블에 저장된 컬럼 중 어떤 컬럼을 선택할지 정하는 부분
예시 쿼리:
SELECT
  kor_name AS name,
  type1
FROM basic.pokemon
```

## 02.

```
개념 이름: WHERE
개념 설명: FROM에 명시한 테이블에 저장된 데이터를, 원하는 조건이 있을 때 그 조건에 맞게 필터링하는 부분
예시 쿼리:
SELECT *
FROM basic.pokemon
WHERE type1 = "Fire"
```

## (선택) 03.

```
개념 이름: 테이블 구조 확인
개념 설명: 원하는 데이터를 정확히 추출하기 위해 쿼리를 작성하기 전에 먼저 어떤 테이블/컬럼이 있는지, 컬럼이 어떤 의미를 가지는지 확인
헷갈린 점: SELECT/FROM/WHERE를 작성하는 순서와, BigQuery가 실제로 쿼리를 실행하는 순서(FROM → WHERE → SELECT)가 다르다는 점
```

# 3️⃣ 확인 문제

프로그래머스는 로그인이 필요하므로, 로그인 후 문제 풀이를 진행해주세요.

## 🧩 문제 1

문제 링크: [모든 레코드 조회하기](https://school.programmers.co.kr/learn/courses/30/lessons/59034)

풀이 과정:

```
- 테이블에서 확인한 컬럼: ANIMAL_ID, ANIMAL_TYPE, DATETIME, INTAKE_CONDITION, NAME, SEX_UPON_INTAKE
- SELECT와 FROM을 작성한 방식: 모든 동물의 정보를 보여줘야 하므로 SELECT * 로 전체 컬럼을 선택하고, FROM ANIMAL_INS로 대상 테이블을 지정했다. 문제에서 ANIMAL_ID순으로 조회하라고 했으므로 ORDER BY ANIMAL_ID를 추가했다.

  SELECT *
  FROM ANIMAL_INS
  ORDER BY ANIMAL_ID;

- 새로 배운 점: WHERE 조건이 없어도 쿼리가 성립한다는 것과 전체를 정해진 순서로 조회하는 요구는 ORDER BY만으로 해결할 수 있다는 것을 알게 됐다.
```

![수행 인증](images/스크린샷%202026-09-14%20오전%201.34.17.png)

## 🧩 문제 2

문제 링크: [아픈 동물 찾기](https://school.programmers.co.kr/learn/courses/30/lessons/59036)

풀이 과정:

```
- 문제에서 요구한 조건: INTAKE_CONDITION이 Sick인 동물만 조회
- WHERE 절로 옮긴 방식: WHERE INTAKE_CONDITION = "Sick" 로 조건을 걸고, SELECT에는 문제에서 요구한 ANIMAL_ID, NAME 두 컬럼만 남겼다.

  SELECT ANIMAL_ID, NAME
  FROM ANIMAL_INS
  WHERE INTAKE_CONDITION = "Sick"
  ORDER BY ANIMAL_ID;

- 정렬 기준이 있다면 사용한 기준: ANIMAL_ID 오름차순
- 새로 배운 점: 테이블의 모든 컬럼이 아니라 필요한 컬럼만 SELECT에 골라 담을 수 있다는 것, 그리고 WHERE의 조건 값이 문자열일 땐 따옴표로 감싸야 한다는 것을 문제에 직접 적용해봤다.
```

# 4️⃣ 이번 주 회고

```
1. SELECT, FROM, WHERE 중 가장 헷갈린 개념: FROM과 WHERE의 의미가 헷갈렸다. FROM은 데이터의 범위를 정하는 부분이고, WHERE는 그 범위 안에서 조건에 맞는 것만 걸러내는 것인데 처음에 둘의 역할 구분이 잘 안 됐다.
2. 문제를 풀 때 가장 자주 확인하게 된 부분: 문제에서 요구하는 컬럼이 정확히 뭔지와 스키마에 있는 컬럼명을 오타 없이 그대로 썼는지를 자주 확인했다.
3. 다음 주 문제 풀이에서 의식하고 싶은 습관: 쿼리부터 바로 작성하지 않고 테이블 구조와 컬럼 의미를 먼저 훑어본 뒤 쿼리를 작성하는 습관을 들이고 싶다.
```
